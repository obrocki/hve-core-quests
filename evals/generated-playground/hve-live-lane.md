# HVE walkthrough: coverage and operator runbook

**Phase 1 is offline.** This design extends the canonical mock-only suite at `bc8f903`. It adds a local trace grader, not a generator, model executor, or second behavioral suite. Phase 2 designates separate Copilot app sessions per provider for generation and eligible HVE teaching steps, subject to review and independently verified eligibility for each use. The user attested to generation and HVE-agent use for Google, Anthropic, OpenAI, Microsoft and Copilot Fusion. That is **user-attested, not independently verified**. Review of this design does not establish eligibility. The [formula](../../.github/skills/legacy-quest-formula/SKILL.md#safety-gate) still requires independent verification for generation and does not support staging workshop material or live model evaluation. `npm run eval` remains closed; there is no override.

## Coverage matrix

Targets below were resolved against the installed **HVE Core 3.2.2** `plugin.json`, agent frontmatter, and skill names. The plugin declares no standalone commands; activate a skill with the host's skill tool or dispatch its qualified agent with the host's task tool. The **native instruction** column is the action text to add to the corresponding turn in the [canonical walkthrough](behavioral.eval.yaml), not a claim that the step ran. Start the first root user message for each quest with the exact line `HVE-QUEST NN`, replacing `NN` with `01` through `12`. One quest may span contiguous follow-ups when a person must answer. Keep the shared artifact and scope rules from Quest 01 for every quest.

None of the 19 mapped targets (11 skills and 8 agents) sets `disable-model-invocation: true`. The Accessibility Planner agent does, so Quest 10 uses the `accessibility` skill, whose contract covers that workflow. Its `user-invocable: false` prevents direct user invocation, not activation through the skill tool.

`S(name)` is an observed skill activation, `A(name)` an observed qualified agent dispatch, `N` the [native trace grader](hve-trace.cjs), and `C` the [canonical artifact grader](behavior.cjs). Sequences shown with `then` must be observed in order. A no-native gate is not an invitation to simulate a person or service. All live cases are **not-run** in Phase 1.

## What a trace can prove

The installed `@github/copilot-sdk` 1.0.32 `dist/generated/session-events.d.ts` describes the persisted Copilot CLI `events.jsonl` envelopes. Vally 0.20.0's `CopilotAdapter` maps `skill.invoked` to `skill_activation` and `tool.execution_start` / `tool.execution_complete` to tool calls and results, but that projection does not preserve all trigger and dispatch evidence needed here. The offline grader uses the raw JSONL directly. Keep it out of both the formula checkout and the playground, in a local location the assessed agent cannot write. Do not attach, copy to the formula repo, or submit it to a model.

The coordinator checked these shapes against real journals from app sessions with HVE Core 3.2.2 installed: skill origin and trigger fields, the child `agentId` and parent tool call in `subagent.started`, and cross-session assignments recorded as root `user.message.data.content` beginning with the sent text. The regression fixture uses those shapes with synthetic values and unknown fields. No actual journal or live session was used in the tests.

| Dimension | Evidence accepted | When missing |
|---|---|---|
| Artifact | Existing `.hve-walkthrough/NN.md` and `.json` pass `checkBehavior`: stable digest, predecessor, required findings, citations and applicable command records. Present but invalid evidence can fail. | `not-run` if either evidence file or an applicable observation is unavailable. |
| Native skill | Original `skill.invoked` with the mapped name, `trigger: agent-invoked`, and matching `hve-core` plugin name/version metadata during the bound root turn or an attributable child. | `not-run`. Preloads, a context load, tool call/result alone, or an assistant claim do not count. |
| Native agent | A built-in `task` or `agent` tool start selecting the exact qualified HVE agent, paired by `toolCallId` to `subagent.started` with that name and a child `agentId`, during that root turn. | `not-run`. A root picker selection, an attempted dispatch, or a differently named producer is not evidence of a started child. |
| Human decision | Separate record from the person entitled to make that decision, outside this grader. No flags, trace claims or receipts promote this dimension. | `not-testable`. |
| Runtime | Independent tool or human observation of the stated behavior. Command records in an artifact are not execution proof. | `not-testable` in this grader. |
| Semantic quality | Separately established evaluation protocol. No LLM judge is configured. | `uncalibrated`. |

Supply the original root `user.message` event **ID**, not its text, timestamp, `messageId` or client ID. The first selected message must bear the quest marker. Each selected message must identify a complete matching root `assistant.turn_start` and `assistant.turn_end` via `turnId`; list any follow-up root message IDs in order, with no intervening root messages omitted. Replay checkpoints and transient events are not evidence. The journal must start with one original `session.start` for the selected work directory and show no intervening working-directory change. If a host omits trigger, origin, turn IDs, qualified agent identity or a stable boundary, or uses only nested/background activities outside that boundary, record `not-run`. A started child does not establish successful completion. The file digest identifies the bytes graded; it does not authenticate their producer. The checks do not attest that every host or session will emit all required fields.

For the offline Vally program adapter, `metadata.native.status` is the native verdict. Vally 0.20.0 transports `not-run` as a grader error because its program grade response has no skip field. Do not count this as a failed quest or combine that grade with the artifact verdict.

## Operator sequence and stop points

1. Record the provider as `google`, `anthropic`, `openai`, `microsoft` or `fusion` and the same named user attestation. Run `npm run live:preflight -- --provider <provider> --attested-provider <provider>` to inspect the requested profile and unobserved values. Exit `2` is expected: it **always** blocks execution. Stop until the design review and the organization's separate checks establish the intended purpose, audience, effective model, actual service, fallback and clean context. The repository has no live executor; even verified generation eligibility does not grant agent access or make fixture staging permissible. Use the instruction-only path while the gates are unresolved.
2. Only under an independently approved generation process, use a fresh local-only destination outside every formula checkout, for example `D:\Code\quest-live\<provider>\<new-system-directory>`. Invent that provider's `SystemName` independently. Give only the four-file pack and permitted labels/destination to the authorized generation process. Do not provide historical labels, a prior playground, attachments or source content. After generation, treat the output as local and not cleared for release. Set up a standalone, local Git repo there, with no remotes, and a baseline commit separate from the quest commits. Do not stage playground content in the formula repository.
3. Verify the copied assets against the original pack before executing the copies. Run the packaged readiness checker locally, check all 12 flags with trusted deterministic tooling without logging recovered values, and run `npm run eval:composition -- '<absolute playground path>'` from the author checkout. Its trusted pack checks already compare assets and exercise the readiness and flag procedures. If claims of offline behavior matter, independently observe them with the network isolated; startup, PNG presence and flag matches do not prove an exercised workflow. Stop on failed or missing prerequisites.
4. For a separately supported and independently approved **HVE teaching workflow**, follow the matrix starting with 01 Documentation. Only use tools permitted by that workflow; do not pass generated output to a model evaluation, use an unverified route, publish, or connect to trackers or email through this lane. For each quest, capture the original host journal and entry IDs, inspect the diff before committing, compare it to the prior quest's commit (the baseline for 01), and verify the required and protected paths using the canonical diff criteria. Make one local commit per completed quest; retain the baseline and commit sequence locally. If a gate blocks the next step, record it instead of substituting another provider, fabricating evidence, or moving ahead as if it passed.
5. Grade an existing local record with the command below. Omit `--trace` and `--entry` if no native observation is available. Use repeated `--entry` only for contiguous follow-up turns of the same quest. The command records separate artifact and native dimensions and does not run the quest, use Git, or verify commit chronology. Exit `0` means a grading record was returned, **not** that every dimension passed; exit `2` means bad usage, missing attestation or an unsafe workspace. The canonical mock spec still validates per-turn diffs on synthetic inputs only.
6. Aggregate counts per dimension, list the exit codes and optional digests, and keep the provider/quest slots aligned. Keep per-invocation model records local. Never copy raw prompts, traces, artifact text, route endpoints, clue values, passenger records or screenshots into the formula repository. Do not rank models or interpret missing evidence as a failure or measured zero cost.

```powershell
npm run live:grade -- --provider openai --attested-provider openai --quest 01 `
  --workspace '<absolute playground path>' `
  --trace '<absolute path to held local events.jsonl>' `
  --entry '<root user.message event UUID>'
```

No actual route was specified by those selectors. The local grader records `native.invocations[].observedModel` from `data.model` on each matched `skill.invoked` or `subagent.started` event. It reports `unobserved` when the event lacks a usable model ID and never fills it from the requested profile. The value records the model reported at activation or launch; it is not proof of inference, effective service or fallback. An `auto` label does not identify the serving model.

In any independently supported workflow, keep other observed settings in the operator's local record: `assistant.usage` may identify the dispatched or responding model and per-call effort; `subagent.configured` describes resolved settings, not proof of dispatch. `session.start` and `session.model_change` describe selections, not the effective serving route. A token budget is not a verified context tier. Keep any field without attributable evidence `unobserved`.
